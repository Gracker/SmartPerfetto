# Codebase-Aware Analysis Rules

Use these rules before touching code-aware analysis, codebase registry, source ingestion, symbol resolution, patch proposal, or code-aware report/UI surfaces.

## Product Boundary

- Treat source code and knowledge-base text as user-owned local material. Authorized owner-facing analysis may display and retain quoted source and knowledge text in local history, reports, exports, and result snapshots; the owner guard withholds only the credentials inside them and canaries, while strict surfaces replace the material whole. Do not copy raw tool payloads into logs, telemetry, opaque provider transcripts, or public artifacts.
- Material-derived history re-enters a later prompt only for the same creator under the same authorization fingerprint. It keeps a private run's question verbatim for that follow-up, and every history read registers the returned questions for strict echo before the model can see them. Owner surfaces show the question under the owner guard (credential patterns only once the run's guards are gone, as after a restart or in a CLI export). Run and session rows store no question text for a run that may have read private material (the run store decides by the row's own marker); logs and message rows keep the placeholder; tenant export omits it.
- A private run reads the same admitted cross-session experience as a public run and never writes any; the learning contract is in `backend.md`. Learned cases are retired: no store reads, exports or accepts them, and a new result carries no learned provenance. A curated case reaches a run only while a curator's attestation covers its current content (`backend.md`); private and public runs read the same admitted cases, background included.
- A private run's HTML report states in its header that it contains private source or knowledge material visible only to its creator. It shows the creator what a public run's report shows, every question, the plan, notes and uncertainty flags included; since no runtime puts that state into a private snapshot, the report reads it from the live runtime under the owner guard.
- Runtime state is restored only from a persisted session that proves it read no private material: its runs' markers, or, when a snapshot has none (older snapshots, and private ones, whose projection drops their runs), a recorded fingerprint with a selection that has none. A private session keeps no SessionContext, which both restore entries also require. A marker proves "public" only as an explicit `false` on both fields; anything else is unknown and restricted. Any other session starts over on `/resume` and in `prepareSession`. `/resume` puts back the session's authorization fingerprint, language, selection and pins, and records a provider change as a continuity break, so the next analysis continues the same session and its history.
- A private run's answer draft passes the owner streaming projection and is withdrawn for the rest of the run at the projection's first alteration; the finalized answer replaces it. A value that only later context identifies as a credential can show until that context arrives (owner-only, live-only, never stored); see `backend.md`.
- Registration makes a codebase selectable; it never attaches source to an analysis automatically. Every run must carry an explicit selection.
- The Web Add and use action may combine registration, disclosed provider consent, and explicit current selection. Register-only leaves selection and consent unchanged; metadata-only selections are never silently upgraded.
- LLM-visible output should prefer `CodeRef` metadata: the issued reference `id` (never the internal `referenceId`) or `chunkId`, relative `filePath`, `lineRange`, `symbol`, `codebaseId`, `buildId`, `vendor`.
- Raw excerpt inspection endpoints remain RBAC-protected. Their transient frontend caches clear on session/trace switch, panel unmount, permission revoke, reindex, and delete; authorized quotations already saved in analysis results are user artifacts.
- `metadata_only` must never send source snippets to providers. `provider_send` still requires per-codebase `sendToProvider` consent.
- Trace/Skill/SQL supports occurrence in the current trace through its evidence contract. `CodeRef` locates source and supplies candidate mechanism context; it cannot prove implementation behavior or raise occurrence or root-cause confidence alone. The model declares no mechanism status; the server computes each source-dependent claim's standing (below).

- At source activation, disclose that relevant snippets go to the configured AI service, quotations can be saved with local results/exports, provider retention depends on its policy/configuration, and source search/read/model work increases analysis time. Never promise third-party zero retention.

## Backend

- Register and preview paths through `PathSecurityGate`; never trust a client-supplied root directly.
- A live registered root is sufficient for bounded `search_codebase` and `read_codebase_file`; an active index is optional acceleration, not an analysis prerequisite.
- Explicit source selection makes authorized tools available to the primary run. The AI decides whether source lookup is needed within the runtime evidence policy and caller budgets; completion does not require a lookup. Source-use status comes only from actual calls; there is no model-declared decision. An incomplete search cannot support a source-absence claim.
- The analysis-context authorization fingerprint (`resolvedAnalysisContext.ts`, format `acf2:`) covers scope, mode, each selected codebase's lifecycle, selection-policy revision, license and consent, and each knowledge source's rights, consent and license; a deleted source reads as unavailable. It holds no index generation, so a rebuild elsewhere revokes no session, conversation or run and hides no history. A record stamped before `acf2` never equals a current value and is never re-stamped: its session is rebuilt, its conversation descriptor is not recovered (the user starts a new conversation), its source-derived history stays stored but out of the model context, and its ledger entries grant no patch authority.
- Each run pins its selected indexes' generations once (`services/indexGenerationPins.ts`) and every index entry point checks them after the authorization check, before reading, after reading and again right before delivering (after filtering and the ledger flush), so a rebuild mid-call is never delivered as "no hits". A generation serves only while its stored data is whole: a registry that still names it proves nothing once its chunks or file are gone, and a partial generation is never served as fewer hits. Registered source indexes (`lookup_app_source`, `lookup_kernel_source`, `lookup_aosp_source`, `lookup_oem_sdk`, `resolve_symbol`, `propose_patch`) serve only the pinned generation while it is active and the store still holds every chunk it was pinned with, else refuse with `codebase_index_generation_changed` / `use_search_codebase` (the live root stays searchable); `resolve_symbol` resolves against the pinned generations, and `propose_patch` takes its target codebases and generations from the lookup ledger (context looked up from a generation this run did not pin refuses the same way), never from chunks a rebuild may already have collected. The Android Internals Wiki lookup refuses any change or lost chunk (`knowledge_index_generation_changed`, `continue_without_private_knowledge`), since its rebuild deletes the older generation. A document collection keeps serving its pinned generation while that file holds every document, section and chunk its manifest sealed (the previous generation is kept; every read makes the same check), else `knowledge_index_unavailable`. One checkpoint reads the selected registrations once for both the authorization fence and the generation check. Authorization changes still revoke the run.
- The run's MCP server decides each selected codebase's capabilities once (`services/codebase/selectedCodebaseCapabilities.ts`: `search`, `read_body`, `index`, `graph`). Graph tools register only when a selected codebase has a GitNexus index, and the index tools (`lookup_app_source`, `lookup_kernel_source`, `resolve_symbol`, `propose_patch`) only when one has an active index; a call naming a codebase without the capability is a policy refusal before any source is reached. The same view, with the run's depth and starting budget, is the system prompt's `source_authorization` segment; its `pathScope` says only whether the registration is filtered (`whole_root` or `registered_filters`), never the filters.
- A well-formed path or search prefix the selection policy or provider-send grant refuses is a policy refusal with a closed `action_required` token (`services/codebase/sourceAccessRefusal.ts`), charged as rejected with zero tokens and not counted as a queried codebase. It points at `search_codebase`, never at the filters: exclude globs can name the private paths they hide. A refusal carries no backend or coverage fields; malformed paths and unreadable files stay thrown failures. `inspect_code_symbol` admits paths by the same selection policy as search and read, so a path search returns is never refused there.
- Accepted residual: the refusal is a string-only oracle that a model-chosen path or prefix lies outside the selection or grant. It is decided before any filesystem access, so it never reveals whether that path exists, and it names no filter, glob or root. Likewise, a provider-send search that withholds a match outside the grant reports `searchIncompleteReason: provider_grant_scope` without its path. That is one bit per search call, and it is adaptive: a model can probe repeatedly (for example extending a fixed-string query one character at a time) to learn whether given text occurs in registered but ungranted files. It is bounded only by the run's source search budget (`strategies/source-depth-policy.yaml`), and never exceeds what `metadata_only` already exposes for the same registration, which returns those files' paths and lines. It is preferred over a false source-absence claim. The refusal action for a prefix outside the grant is `continue_without_this_path_prefix`, not a retry.
- Every returned item carries its issued reference `id`, the one id the model cites, the echo CodeRef label shows and the ledger keeps (a lookup's own `referenceId` never leaves the runtime). A search hit is `lookupKind: search_hit`, with or without context text: it locates code. Only a read window (`body`) or an indexed chunk delivers evidence; a bound search hit counts as read when issued body references of the same file and known source generation together contain its whole range (`referenceHasReadBody`; a reference with no known generation is its own version), never beyond its own range. Status follows the strongest finding (`corroborated` > `located` > `search_incomplete` > `not_found_complete`/`attempted`) and is no longer pinned by one incomplete search; run `coverageComplete` stays monotone, and negative source claims check it. A read window, failed or refused, states nothing about search coverage.
- Only codebase-wide coverage supports `not_found_complete`. A search narrowed by `path_prefix` reports `coverageScope: path_prefix`, and its complete empty result leaves the decision `attempted`.
- A search ranks every match its traversal reached and verifies only the top-ranked through the gate. Showing fewer than exist is paging (`moreResults`), never incompleteness; a traversal that stopped early (`traversal` other than `complete`) or a grant-withheld match is. On-demand search and read use their own file-size limits (16 MiB scan, 4 MiB body), separate from the indexing limit; a hit above the body limit returns its location only. The model reads one line-numbered body; the raw text stays internal for echo registration and accounting. `find_codebase_files` returns relative paths only and issues no source reference. `locate_trace_anchor` (`services/codebase/traceAnchorLocator.ts`, normalization and ranking in `strategies/source-anchor-normalization.yaml`) spends one `locates`, runs at most a few bounded internal searches, returns locate-only `search_hit` references and never states coverage or absence; the redacted line text it ranks by (`matchLineTexts`) is internal and stripped before delivery in every mode. A thrown source-tool failure reaches a runtime only as a closed path-free code (`source_tool_failed` otherwise).
- Source budgets are per run, in memory with the run's MCP server (`services/codebase/sourceBudget.ts`), sized by the effective depth (`resolveEffectiveSourceDepth`: an explicit `sourceDepth` wins; `auto` follows the turn intent's `sourceNeed` — `mechanism` reads how code behaves, `none`/`locate` only locate — and the run's budget mode when the intent did not say; `metadata_only` caps at `locate`; limits in `strategies/source-depth-policy.yaml`). The decision (`requested`, `effective`, `origin`, fallback reason, cap) is stored as `SourceUseDecisionV1.depth` and stated once per run in the owner's progress. Depth sizes the budget and selects the recipe (`sourceNeed: none` gets none); graph navigation is offered at both depths, `propose_patch` only at `mechanism`. Depth never decides the semantic review: a run with source access is reviewed at either depth, since authorized source-derived history reaches the prompt without a tool call. Counts are spent when a call reaches the source; tokens for what is delivered, truncating rather than refusing whole (metadata-only graph and symbol tools refuse whole, before issuing references). Retrieved knowledge (Knowledge Pack, private Wiki, document collections) has its own pool, and document collections their own call counts and part size; `lookup_knowledge`'s built-in methodology templates are product prompt content and are not budgeted. `CodeLookupLedger` is audit and patch authority only, so a torn ledger record affects patches, not lookups. Every runtime passes the effective depth; none sizes a budget on its own.
- On-demand access must enforce the registered path filters, extension/size limits, provider consent, bounded results/line ranges, secret redaction, and the private-output projection. Never return an absolute root.
- Credential redaction has one detector, `services/security/secretPatterns.ts`, for model-facing source (on-demand reads, ingestion, retrieval), knowledge and questions, and the owner guard; public artifacts add the broad legacy rules on top. It judges a whole file in that file's syntax, so redact before windowing or chunking, never a window alone. It replaces values only and keeps every line break. A detector change is checked in both directions: `secretPatterns.test.ts` holds the leaks (every split point of the owner stream included) and the code it must leave readable, and its time bounds catch quadratic paths. Redaction is one layer of defense in depth with known heuristic limits (keyless random strings, file types it does not map, formats it reads only approximately); it is never complete. The owner guard uses its keyed rules only, so commit hashes and ids stay readable to the owner. Correctness does not depend on the detector being complete: `provider_send` consent decides whether source reaches a provider at all, strict projections replace private material whole on logs and public artifacts, and the echo guards withhold registered text wherever it recurs.
- A `document_collection` knowledge source (`services/knowledge/`) is read through the knowledge-root gate, redacted whole before and again after format conversion, and indexed into one SQLite FTS5 file per generation under the user data directory (`knowledge/<scope hash>/<source id>/`), written to a staging file, renamed whole and made current only by the fenced `activateGeneration`; the current and previous generations are kept. Indexing and owner search need the rights acknowledgement only (`requireIndexAccess`); provider-send consent (`evaluateAccess`) alone decides whether its text may reach a model, and an omitted `sendToProvider` on re-registration keeps the consent in effect, never one a dual-write side revoked. Every registry mutation sees both store sides' denials (`withDenialsOf`). Deletion rewrites the fenced `deleting` tombstone on every side first, which reads as absent and refuses every mutation, then removes the index in lease-fenced batches, then the records (DB copy first); whichever step fails, every remaining record is a tombstone and a retry finishes it. The `/api/admin/rag/knowledge` routes and `smp knowledge` (`preview|register|list|reindex|remove|search`) share the registry, `DocumentCollectionIngester` and store; registration requires the explicit rights acknowledgement (`--accept-rights`), and the CLI trusts the local user's own folder in place of `SMARTPERFETTO_KNOWLEDGE_ROOTS`, as `smp codebase` does. No management output names a registered absolute root.
- A selected `document_collection` reaches the model only through `search_knowledge` / `read_knowledge_section`, registered when a selected source has rights, provider-send consent and an active index; run authorization refuses any other selection, so there is no metadata-only tier (titles and paths are document content too). They are `evidenceEffect: background`: informational for plans, no DataEnvelope or capture, never paced, callable under `existing_only`. A hit's `kref-` reference is random, issued only for what was delivered, bound to the run's scope, source, pinned generation, section and document path, and resolves in no other run; it is neither trace evidence nor a source reference, so a declaration citing it fails verification. Each call rechecks the authorization context and pinned generation before reading and before returning; delivered text passes evaluation admission and `recordInjection('knowledgeDocs')`, is registered for echo with its title, headings and path matched as whole values (at least two code points; `registerKnowledgeTextForEcho`), and is projected outward as counts and ids only, any unrecognized shape a rejection (`toolResultProjectionFilter.ts`). The prompt gets a separate `knowledge_authorization` segment (descriptions capped at 120 characters) and `prompt-knowledge-use-*`, Claude sub-agents too, whatever the source mode. Both are optional background and droppable, the first to go under prompt-budget pressure (guidance, then the list of bases), so comparison and evidence context survive; the tools still search every selected base without an id.
- Code-aware chunks must carry `codebaseId` and `registryOrigin='codebase_registry'`.
- `app_source`, `kernel_source`, or registry-origin chunks missing codebase metadata must fail closed with `invalid_codebase_metadata`.
- Indexed lookup handlers must pass through `LookupResponseFilter`; on-demand handlers must pass through `OnDemandSourceAccessService` and the same external-surface projection boundary before results leave the runtime.
- SSE/snapshot/report/export paths use the owner-result projector; logs and public artifacts use the strict projector. Never pass raw MCP tool results directly to either audience. Keep audience scopes synchronous and exception-safe, and fix streaming audience at construction.
- Parse native conclusion declarations before display replacement. Keep original verification values in the private finalization context and bind them to the exact run, attempt and public candidate with an issued receipt. Never verify rewritten display values or recover validation authority from serialized output. Project protocol fields structurally and serialize text values safely; preserve invalid native declarations as invalid.
- `SourceUseDecisionV1` is actual current-run MCP state, not model-authored prose. It records selected/queried/used IDs, status, structured reason code, coverage, and safe references. `pending` and `attempted` are audit states and do not override native completion or make the answer partial by themselves. Unchecked source claims remain unverified; actual invalid bindings and private-output projection failures retain their separate verification and delivery consequences.
- Issue model-visible `sourceReferences` before delivering lookup results; admit them into the current-run ledger before exposing associated body or authorizing patches. At reference capacity, return an explicit bound instead of silently dropping issued references. Accept safe relative Unicode and spaced paths consistently across reading, source identity, reports, and verification.
- An explicit stop decision cannot hide subsequent actual source calls. A requested file window is not incomplete search coverage; preserve real search incompleteness while allowing bindings to positively identified source.
- `knowledge_use@1` (`services/knowledge/knowledgeUse.ts`) records what a run delivered from its selected knowledge bases: `sources[]` (`knowledgeBaseId`, `kind`, pinned `generation`, distinct `deliveredReferenceCount`) and the answer's `kb:path#Lx-Ly` citations (backtick-quoted when the path has spaces), read with the source-citation scanner. A citation is `delivered` only when the delivered text covers its lines (a search excerpt that was its hit's whole text, or a section read whole in uncut parts), `located` when only delivered locations cover them, `unmatched` otherwise, `ambiguous` when several bases or generations hold a covering document; an invalid range keeps no lines and is unmatched. Usage is recorded after the evaluation filter on what was returned (zero hits, refusals, filtered and repeated content never count); the Wiki has no line references and is counted only. Only finalization sets it, from the run's delivery record (its finalization context's, or the run-bound record a runtime keeps on a failure it returns without one) and the final body; it is display and audit, never claim verification, finite proof or a delivery verdict. It travels with the delivery fields (`copyAnalysisDeliveryFields`, closed shape, in which every base a citation names is a listed document collection that delivered): the owner keeps its citations, strict surfaces keep the sources only; an absent field (older result, or no finalization) means not recorded, never zero. It is a result surface: a run that throws, or a cancel (which stores only its marker), has no result to carry it. Accepted residual: what such a run sent to the provider is recorded only as RunManifest `knowledgeDocs` injections, which persist only for HTTP agent runs with RunManifest persistence available; conversation runs attach no RunManifest lifecycle and CLI manifests are in memory, so those failed or cancelled runs keep no durable record of delivered knowledge (no record existed before either). No separate cancel-time knowledge record exists. The receipt's optional `nonEvidenceContext.knowledgeReferenceCount` follows the same rule, and a malformed count is dropped alone.
- `SourceClaimBindingV1` is `{claimId, sourceReferenceIds, traceEvidenceRefIds?}` and uses only references returned by the current selected partition; any Trace references must belong to the same claim. Legacy `mechanismStatus`/`reason` and `semantics.source` are accepted and dropped. `source_claim_verifier@2` (`sourceClaimVerifier.ts`) judges every source-dependent claim (a `source.*` predicate, `codebase` population, a binding, or a written citation): `invalid` (an unissued or out-of-selection reference, or a Trace ID matched to no evidence of that claim) is the only error and fails the gate; `unbound` (no binding, or an unmatched/unpinned citation in its text or visible block), `location_only` (no read body per `referenceHasReadBody`), `source_only` (no matched same-claim Trace, or no answer block cites it) and `trace_linked` follow in that order, all short of proof, so the answer is `~` at best. Body citations (`path:L10-L20`, backtick-quoted when the path has spaces) are matched by `sourceCitations.ts`: exact path first, else trailing segments; one codebase/file/source generation gives `verified_body` or `located`, several are `ambiguous`, which a claim bound to one of its candidates pins for that claim only. There is no `source.location` finite proof; a stored `@1` result stays readable.
- Initial/replayed SSE, HTML reports, CLI JSON/Markdown/HTML, analysis-result snapshots, and report/snapshot APIs share the canonical owner projector. Source quotations and real check diagnostics remain readable even when success is false; preserve verification/completion status. Strict source-echo capacity limits must not suppress owner output. The Web receipt remains metadata-only with no CodeRefs; do not expose registered absolute roots or credentials.
- Owner process views retain model-provided analysis commentary and shared tool/outcome narration; raw tool payloads remain outside chat. Source-tool narration for the owner is built from the tool's own result (counts, relative file names, read ranges, budget stops) plus one per-run source-depth line; strict surfaces keep the path-free receipt wording. Strict private process projections may omit model events without repetitive placeholders. Receipt mechanism status comes from the actual source-claim verifier, never a model declaration. Index failure messages must distinguish capacity failure from fresh root access checks; source access scope affects both indexed and on-demand paths.
- Keep prompt content in `backend/strategies/` and Skills in `backend/skills/`; do not hardcode code-aware prompting in TypeScript.

## Patch Proposals

- `propose_patch` requires prior successful code lookup in `CodeLookupLedger`.
- On-demand `referenceId` records deliberately do not authorize `propose_patch`; patch targets remain tied to previously looked-up indexed `chunkId` context.
- Reject context from multiple codebases in Phase 1.
- Verify target files are inside previously looked-up context.
- Run `git apply --check` in the target codebase root before returning a `verified` patch.
- `sketch` and `unverified` responses must not expose copyable unified diff text.

After backend changes:

```bash
cd backend
npm run typecheck
npm run validate:strategies
npm run validate:skills
npm run test:scene-trace-regression
```

After plugin UI changes:

```bash
./scripts/start-dev.sh
# Stop the dev server after browser verification.
(cd perfetto && tools/node ui/build.mjs)
./scripts/update-frontend.sh
```

Before landing:

```bash
npm run verify:pr
```

For full code-aware validation:

```bash
npm --prefix backend run verify:codebase-aware
npm --prefix backend run test:source-claim-contract
npm --prefix backend run test:report-contracts
npm --prefix backend run verify:code-aware-semantic-delta
```

This gate depends on local Heavy/Light traces plus a local
`HighPerformanceFriendsCircle` checkout. It verifies both no-codebase
trace-only behavior and configured-codebase reports/exports with source-level
`CodeRef` assertions.

`verify:code-aware-semantic-delta` is deterministic local evidence. It must
cover A0 no source, A1/A2 no-index access, A3 indexed access, A4 wrong-source
rejection, quantitative `not_needed`, source-binding strength, and the shared
runtime finalizer. Report real-provider acceptance separately; unavailable
credentials are `REAL PROVIDER NOT AVAILABLE`, not a pass.
